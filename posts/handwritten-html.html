为什么我用纯手写 HTML 做个人主页

用现成的模板站，十分钟能生成一个看着还不错的个人主页。用前端框架，熟练的人半小时也能把骨架搭完。

但这个页面，我断断续续写了好几个晚上。

有人问值不值。我的回答是：如果目标是「尽快有一个网站」，不值；如果目标是「搞明白网站到底是怎么来的」，那太值了。

模板的问题不是丑，是没有一句是我说的

一开始我用的是在线模板。选主题、换配色、填文字，很快就能导出。但用了几天，我越来越别扭，因为页面上的每一句话都在替我说一些我并没有说过的话。

比如技能栏里那些百分比。

「HTML · 90%」「CSS · 85%」「JavaScript · 75%」

问题是，谁定的这个数？我连一条完整的 DOM 事件流都讲不清楚的时候，凭什么写 75%？这类数字看起来精确，实际上什么都没表达，反而暴露了自己没想过。

模板给的是填空题，但个人主页其实是一道论述题。填空填得再整齐，论述题也是零分。

手写之后，我第一次看清浏览器在干什么

抛开框架，很多平时被自动处理掉的东西就必须自己面对了。这个过程有点像拆开一台用惯了的机器。

层叠到底是怎么工作的

以前改样式基本靠改一个值、刷新、不行再改。手写之后被逼着去理解：为什么这个颜色没生效，为什么加了 !important 才好——然后发现真正的原因是选择器权重算错了，!important 只是在掩盖问题。

一旦理解了层叠，改样式就从试错变成了推理。

响应式不是加个媒体查询

我最初的做法是：桌面端写完，加两个 @media，字号调小一点，收工。结果在手机上一看，导航挤成一团，正文横向溢出，头像把标题压得喘不过气。

后来才明白，响应式的核心不是断点数量，而是布局在什么条件下会失效。窄屏下真正的问题是水平空间不够分配，那就得换一种组织方式：从并排改成上下堆叠，从固定宽度改成相对单位。

我现在的做法是先把窗口拖到最窄，从最小的屏幕往上写，而不是从大屏幕往下砍。

可访问性不是给别人做的

键盘焦点、语义标签、对比度——这些词以前我觉得很遥远。直到我自己试着只用键盘操作一遍：按 Tab 跳到第二个链接之后，我完全不知道焦点去哪了，因为页面上没有任何视觉提示。

那一刻我意识到，这不是「为残障用户做的适配」，这是页面本身缺了一块。补上一行 :focus-visible 的样式，成本几乎为零，但可用性的差别是「能用」和「不能用」。

代价是什么

说实话，代价很清楚，不该藏着：

  • 重复劳动。加一篇文章，就得复制一份 HTML，改标题、改正文、改上一篇下一篇的链接。三篇还行，三十篇会疯。
  • 改一处要动多处。颜色变量统一了还好，但我第一版是硬编码色值，换个主色要全局搜索替换，还漏了几处。
  • 没有热更新。改完保存，手动刷新，来回切窗口。效率确实不如框架的开发服务器。

所以我做了一个折中：样式用 CSS 变量收口，内容用 Markdown 写，再转成静态 HTML。这样既有手写的可控性，又不至于每篇文章都从零复制。

那到底什么时候该用框架

我现在的判断标准很简单，看三件事：

信号说明
状态变多页面上有大量互相影响的状态（登录、筛选、分页、表单校验），手写会迅速失控
要协作多个人同时改代码，需要组件约定和构建流程来对齐
要长期迭代内容量会持续增长，重复劳动的成本会指数上升

反过来，如果一个页面的主要工作是展示而不是交互，手写反而更快、更轻、更容易维护。一个个人主页，恰好落在这个区间里。

最后说一句可能有点扫兴的话：手写 HTML 不会让你变成更好的工程师，它只是让你少了一层遮蔽。真正的能力还是在于判断——判断该用什么、该省什么、哪里值得较真。

这个页面还会有很多问题，我会一边用一边改。如果哪天它变得太复杂，我大概会老老实实换个工具。

工具是手段，不是身份。
